# Баннеры активностей

Управление: `/admin/activity-banners` (ссылка в управлении гильдией). Создание, поиск, редактирование и удаление с подтверждением доступны владельцу и администратору через `activity_banners.manage`.

Поля: название 3–120 символов, фото PNG/JPEG/WebP до 10 МБ (обрезается по центру до широкого PNG 480×180), коэффициент 0,01–1000 с точностью до сотых. Фото можно заменить или убрать. Реестр и публичная сетка в `/events` имеют страницы по 20 записей; сами баннеры видят активные участники гильдии.

Организатор выбирает баннер при создании нового события. Название события можно уточнить. В событии сохраняется снимок названия баннера, фото и коэффициента; повтор запроса не дублирует событие. Изменение и удаление шаблона не меняет существующие события. Новые события с баннером используют сохранённый коэффициент в статистике взвешенной посещаемости Прайма; общий процент остаётся отношением присутствий к применимым событиям. Финансовые проводки не пересчитываются. Для событий без баннера сохраняются прежние правила.

Миграция `202611090020_activity_banners.sql` добавляет отдельный реестр, право управления, защищённые RPC, RLS и четыре nullable-поля снимка в `events`. Не требует финансовых миграций 017/018; существующие события остаются без снимка. Миграция выполняется до публикации нового приложения через проверенный проект Supabase для APP_ORIGIN https://xd-guild.ru. Токен применяется только в GitHub Actions и не выводится в логи.

Проверки: PostgreSQL-тесты на рабочей схеме без 017/018 (CRUD, полномочия, RLS, аудит, дубли, диапазон коэффициентов, версии, снимки, повтор запроса после удаления шаблона, откат неудачного создания); приоритет сохранённого коэффициента в аналитике; production Next с локальной имитацией Supabase (фото, CRUD, публичный баннер, выбор для события, ширины и темы).
