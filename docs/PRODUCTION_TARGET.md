# Рабочий сайт XD

Единственный целевой домен этого обновления: **https://xd-guild.ru**.

Подтверждено через SSH с публичным ключом хоста, предоставленным пользователем:

- nginx направляет xd-guild.ru на 127.0.0.1:3001;
- приложение — `guild-dashboard`, `apps/web`, Supabase Auth/PostgreSQL;
- systemd service: `xd-guild`; исходный рабочий каталог `/var/www/xd-guild-command-center/apps/web`;
- исходная ветка `codex/xd-foundation-20261031`, commit `e5c90bb`;
- `guild-dashboard-next` на порту 3000 — отдельная устаревшая SQLite-версия. Она не должна подменять данные или вход на xd-guild.ru.

Из ТЗ перенесены визуальная концепция, типографика, существующая графика, интерактивные графики, настройки панелей и отдельная статистика. Действующие события, персонажи, роли, начисления, выплаты, отмены, CSV и Supabase RLS сохранены.

Новые `/statistics` и `/statistics/export` читают существующие записи в пользовательском контексте. Отменённые/будущие/неподтверждённые события исключены; уважительные причины и неприменимые отметки исключены из знаменателя. Веса Прайма используют сохранённый вес босса, когда он присутствует, и полную таблицу правил из ТЗ для старой схемы без этих колонок. Это аналитический показатель; денежные проводки не переклассифицируются.

На рабочем сервере схема не содержит `events.boss_name`. Поэтому отчёт поддерживает старую схему, а функции новых справочников/общих фондов не требуют принудительного применения миграций 017/018 для этого выпуска. Каталог и редактирование коэффициентов показываются по действующим разрешениям; новая ссылка общего фонда РБ показывается только при наличии соответствующей таблицы. Миграции, перенос пользователей, замена БД и изменение денежных правил в этом выпуске не выполняются.

Расчётные диапазоны 15→15 служат фильтром отчёта; существующие начисления не пересчитываются. История прошлых периодов читает журнал и не выдаётся за новый неизменяемый снимок всей базы. Убийства/честь/результаты PvP не выдумываются: текущая схема хранит посещение PvP, остальные показатели требуют отдельного расширения модели.

Проверки: 121 тест, TypeScript, production build. Дополнительно `scripts/check-command-center.py` проверяет production Next с изолированной имитацией Supabase, включая старую схему без весов, пять разделов на шести ширинах в двух темах, закрытый доступ, CSV и сохранение панелей. Рабочие аккаунты в локальных тестах не используются.

Перед переключением сохраняются service и конфигурация приложения в закрытый каталог; сборка выполняется в отдельном каталоге релиза. Неуспешный запуск возвращает старый service. Все проверки относятся именно к xd-guild.ru. Секреты и тела ответов с рабочими данными в CI не печатаются.
