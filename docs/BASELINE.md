# Обнаруженный существующий проект

Статический обзор 2026-10-30, без подключения к БД/таблице и без проверки production. Это не полный аудит безопасности.

Основа: Express, pg, cookie-session; PostgreSQL-таблица users; игровые данные читаются из Google Sheets. Есть вход, создание первого офицера, управление пользователями, обзор, участники, казна, аукцион, калькулятор рейдов. В репозитории нет Next.js и TypeScript. Нельзя утверждать, что эти функции работают в production, только по наличию кода.

## Подтверждённые расхождения с новой спецификацией

- `server.js`: fallback секрета cookie на строку разработки. Для новой версии — fail closed без секрета; существующий секрет не проверялся.
- `src/auth.js`: доступ/роль читаются из сессии, состояние пользователя в БД на каждом запросе не перепроверяется. Блокировка/понижение роли не обеспечивает немедленный отзыв уже открытой сессии.
- `server.js /api/setup`: создание первого офицера через публичный endpoint и отдельную проверку COUNT. В новой версии нужен закрытый атомарный bootstrap владельца.
- `src/db.js`: TLS-проверка сертификата PostgreSQL отключена через rejectUnauthorized:false. Это не переносить в новую архитектуру.
- Пользователь создаётся с username; нет требуемого отдельного onboarding, согласий, pending-заявок, нормализации игрового ника и набора разрешений.
- `src/sheet.js`: загрузка таблицы рассчитана на доступ по ссылке. Для закрытых персональных/финансовых данных новая система использует приватную БД и RLS.
- `/api/data` удаляет Treasury из общего кэшированного объекта для member. Это может повлиять на последующий ответ officer до обновления кэша. Зафиксировано для отдельного исправления, исходники сейчас не менялись.
- Старый калькулятор предлагает долю гильдии 10%, master prompt требует 30% по умолчанию. Старую историю нельзя молча пересчитать.

## Переход

Сначала уточнить использование текущего сайта. До миграции экспортировать БД и таблицу; не считывать/публиковать реальные данные ради макетов. Новые аккаунты сопоставлять с прежними только после проверки, не по совпадению ника. Пароли и права не переносить вслепую. Новая схема создаётся миграциями отдельно. Сверить количество записей, ники, суммы, роли и сценарии аукциона/калькулятора. Существующий сервис остаётся до проверки замены и согласованного переключения; иметь проверенный путь отката.
