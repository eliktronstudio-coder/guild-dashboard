# Подключение XD: инструкция для владельца

Обновлено 2026-11-01. Код находится в `apps/web`. Подключение Supabase в рабочей среде пока отсутствует; реальный вход и первый деплой пока не проверены. Начните с шага 1 — остальные шаги можно пройти последовательно с телефона.

## 1. Создайте бесплатный проект Supabase

1. Откройте https://supabase.com/dashboard и войдите через свой GitHub.
2. Нажмите **New project** в своей организации на **Free**. Название: `xd-guild`.
3. Задайте пароль базы, сохраните в менеджере паролей. Его не нужно присылать в чат.
4. Выберите доступный регион ближе к участникам и дождитесь готовности проекта.
5. Не подключайте платные дополнения. Free достаточно для первого небольшого запуска; фактические лимиты смотрите в Dashboard → Usage.

После создания достаточно сообщить «Supabase создан» и адрес проекта вида `https://….supabase.co`. Пароль базы, secret/service-role ключи и токены бота в чат не отправляйте.

## 2. Примените схему базы

В новом проекте откройте **SQL Editor → New query**. Скопируйте целиком файл [202610310001_foundation.sql](../apps/web/supabase/migrations/202610310001_foundation.sql) и выполните один раз.

**Для новой версии нужны шесть миграций по порядку:**

1. `202610310001_foundation.sql` — основа.
2. [202610310002_members.sql](../apps/web/supabase/migrations/202610310002_members.sql) — профили, персонажи и история ников.
3. [202610310003_events.sql](../apps/web/supabase/migrations/202610310003_events.sql) — события и запись.
4. [202610310004_event_lifecycle.sql](../apps/web/supabase/migrations/202610310004_event_lifecycle.sql) — закрытие, версии и аудит событий.
5. [202610310005_attendance.sql](../apps/web/supabase/migrations/202610310005_attendance.sql) — посещаемость, отчёты, безопасное повторение создания и редактирование.
6. [202610310006_treasury.sql](../apps/web/supabase/migrations/202610310006_treasury.sql) — четыре казны, два инвентаря, продажи и история.

Каждый файл выполнить отдельным запросом целиком и дождаться успеха перед следующим. Если 001–002 уже выполнены, добавьте только 003–006. Если выполнены 001–005, нужна только 006. Уже применённые миграции повторять не нужно. Новая версия приложения ожидает все шесть; обновляйте приложение после схемы. В существующей тестовой базе предварительно сохраните резервную копию. 001–005 не изменены; последующие миграции сохраняют аккаунты, заявки, членство и роли. Завершённые события, созданные до 005, потребуют первой проверки отметок.

Первая миграция создаёт гильдию XD, профили, заявки, членство, роли, разрешения, отзыв сессий, журнал и RLS. Она не назначает первого зарегистрировавшегося администратором. Не выполняйте её в базе старого Express-сайта. Если выполнение завершилось ошибкой, сохраните её текст без персональных данных и секретов; не удаляйте таблицы для повторной попытки.

## 3. Получите публичные параметры

В **Connect** или **Project Settings → API / API Keys** найдите **Project URL** и **Publishable key** (`sb_publishable_…`). Названия разделов могут немного меняться. Секретный ключ `sb_secret_…` / `service_role` для веб-приложения не требуется.

Параметры добавляются в Vercel → Project → Settings → Environment Variables, а локально — в `apps/web/.env.local` по примеру `.env.example`:

| Переменная | Значение |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Project URL |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | Publishable key |
| `APP_ORIGIN` | Точный HTTPS-адрес нового сайта, без `/` в конце |
| `AUTH_TELEGRAM_ENABLED` | Пока `false` |
| `AUTH_TELEGRAM_PROVIDER` | `custom:telegram`, не переименовывать |
| `AUTH_EMAIL_ENABLED` | Пока `false` |
| `AUTH_EMAIL_DELIVERY_READY` | Пока `false` |

## 4. Создайте отдельный проект Vercel

1. На https://vercel.com/new выберите личный бесплатный Hobby для некоммерческого проекта и репозиторий `eliktronstudio-coder/guild-dashboard`.
2. Имя нового проекта — например `xd-guild-command-center`, **Root Directory — `apps/web`**, Framework — Next.js, Node — 24.x. Старый сервис оставьте как есть.
3. Выберите ветку с новым приложением. Код находится в ветке `codex/xd-foundation-20261031`, [PR №1](https://github.com/eliktronstudio-coder/guild-dashboard/pull/1). Пока изменения в draft PR, `main` ещё не содержит `apps/web`; не пытайтесь разворачивать из неё новый сайт. Для первого preview используйте ветку PR, либо сначала завершите проверку и слияние.
4. Укажите переменные из шага 3. Для первого запуска без параметров приложение покажет подготовку, это ожидаемо.
5. После получения адреса `.vercel.app` задайте его как `APP_ORIGIN` и выполните **Redeploy**. Нельзя оставлять `localhost` в облачном окружении.
6. В Supabase **Authentication → URL Configuration** задайте **Site URL** = `APP_ORIGIN`; разрешите точные redirect URLs: `https://ВАШ-САЙТ/auth/callback` и `https://ВАШ-САЙТ/auth/callback?next=/account/password`. Для локальной разработки отдельно добавьте точный `http://localhost:3000/auth/callback`.

Не используйте широкие wildcard callback URLs для production. Preview не подключайте к рабочим персональным данным; для него нужна отдельная тестовая база либо отключённая авторизация.

## 5. Настройте Telegram-вход

Бот для входа и будущих уведомлений можно создать через официальный **@BotFather**. В разделе Web Login / Allowed URLs зарегистрируйте origin сайта и точный callback, который покажет Supabase при создании custom-провайдера. Возьмите **OIDC Client ID и Client Secret** — не подменяйте их случайными значениями или username бота.

В Supabase **Authentication → Sign In / Providers → New Provider**:

- Тип **Auto-discovery (OIDC)**.
- Identifier: **`custom:telegram`**.
- Issuer: **`https://oauth.telegram.org`**.
- Client ID / Client Secret: из BotFather; вводятся только в защищённые настройки Supabase.
- Scopes: **`openid profile`**. Номер телефона не запрашиваем.
- **Email optional: true** — Telegram не предоставляет email.
- **PKCE: enabled**, проверка nonce включена (`skip_nonce_check=false`).
- При возможности сохранения custom claims разрешите `id`. Идентичность определяется проверенным subject провайдера; для будущей связи с Bot API нужен числовой Telegram ID, не username.

Telegram не публикует UserInfo endpoint. Используется проверенный ID token; не выдумывайте UserInfo URL и не отключайте проверку подписи/issuer/audience/nonce для обхода ошибок.

Если Dashboard не показывает необходимые расширенные параметры, есть [скрипт настройки](../apps/web/scripts/configure-telegram.mjs). Он запускается в доверенной среде с защищёнными переменными `SUPABASE_URL`, `SUPABASE_SECRET_KEY`, `TELEGRAM_CLIENT_ID`, `TELEGRAM_CLIENT_SECRET`. Эти секреты не нужны браузеру или обычному runtime сайта. Скрипт создаёт провайдера и не перезаписывает существующего. Его выполнение на реальном проекте ещё не проводилось.

Затем установите `AUTH_TELEGRAM_ENABLED=true` в тестовом окружении, сделайте Redeploy и проверьте вход. Должен открыться экран обязательного ника, а не закрытая статистика. Если связка конкретных настроек OIDC не работает, оставьте публичный вход выключенным и сохраните сообщение ошибки для диагностики.

## 6. Назначьте себя владельцем

1. Войдите через подтверждённый аккаунт. Можно остановиться на экране игрового ника.
2. В Supabase **Authentication → Users** найдите свой аккаунт и скопируйте его внутренний UUID. Проверьте, что это именно ваша идентичность.
3. Откройте [bootstrap-owner.sql](../apps/web/supabase/operations/bootstrap-owner.sql), замените UUID и `ВашНик`, выполните через SQL Editor.
4. Перейдите на `/dashboard`. Должно появиться управление заявками. Повторный bootstrap запрещён.

Публичного endpoint «создать первого администратора» нет. Совпадение игрового ника не подтверждает владение аккаунтом.

## 7. Почта — после реальной проверки отправки

Если SMTP ещё не настроен, оставьте email-флаги `false`: Telegram-вход позволяет запуститься без почтового сервиса. Email/пароль остаётся частью требований, но не считается проверенным до настройки.

1. Настройте собственный SMTP в Supabase. Встроенная тестовая почта Supabase ограничена и не подходит для открытой регистрации.
2. Включите **Confirm email**, задайте минимальную длину пароля 12, настройте rate limits. Проверьте отправку на несколько реальных адресов.
3. Email template **Confirm signup**: ссылка `{{ .SiteURL }}/auth/confirm?token_hash={{ .TokenHash }}&type=signup`.
4. **Reset password**: `{{ .SiteURL }}/auth/confirm?token_hash={{ .TokenHash }}&type=recovery`.
5. После проверки выставьте `AUTH_EMAIL_ENABLED=true`, `AUTH_EMAIL_DELIVERY_READY=true` и сделайте Redeploy. Проверьте подтверждение, истёкшую/повторно использованную ссылку, восстановление и новый пароль.

Смена пароля требует свежей аутентификации за последние 10 минут. После смены приложение завершает сессии. Привязка/отвязка способов входа пока не реализована — не создавайте второй аккаунт ради обхода этого ограничения.

## 8. Проверка перед приглашением участников

- Утвердить опубликованные тексты `/rules` и `/privacy`: сейчас это стартовые редакции. Указать контакт владельца, сроки хранения и порядок удаления данных.
- Двумя тестовыми аккаунтами пройти вход → ник → заявку → одобрение/отказ → доступ. Первый ожидает подтверждения и не видит состав; второй администратор принимает решение.
- Проверить повтор заявки, конфликт ников, блокировку открытой сессии, смену роли и выход на всех устройствах.
- Добавить двух персонажей, переключить основного, архивировать его; проверить профиль с другого аккаунта, сменить ник и проверить историю.
- Пройти сценарий событий из [STAGE3.md](STAGE3.md): проверить запись, завершение, все отметки, подтверждение отчёта и исправление; обычный участник не должен менять отметки или видеть чужой отчёт.
- Проверить казну: прайм-продажа на 100 000 → 70 000 + 30 000, мини РБ без удержания, частичная продажа, остаток имущества и отмена. Обычный участник не должен создавать продажи. Подробности: [STAGE4.md](STAGE4.md).
- Проверить реальный телефон и Telegram webview, cookie/callback-поведение, письмо на другом устройстве.
- Настроить экспорт и проверить восстановление базы на отдельном тестовом проекте. Бесплатный тариф сам по себе не является планом резервного копирования.
- Только после этого приглашать участников. Перенос старых данных и переключение работающего сайта выполняются отдельно.
