# Telegram-бот XD — подключение с телефона

Это бот для личных сообщений, событий и начислений. Он не создаёт игровой аккаунт и не меняет способ входа. Вход через Telegram OIDC по-прежнему настраивается отдельно по SETUP.md. Достаточно существующего подтверждённого входа через email, чтобы подключить бота после одобрения заявки.

## 1. Подготовить сайт и базу

Нужен работающий HTTPS-сайт XD и подтверждённый аккаунт владельца. Примените только недостающие миграции 001–010 по порядку. Для уже обновлённого до этапа 5 проекта нужны `202611010009_telegram.sql` и затем `202611010010_telegram_participation.sql`. Прежние миграции не повторять. Обновите приложение после базы.

## 2. Создать бота

Откройте официальный [@BotFather](https://t.me/BotFather), выполните `/newbot`, задайте название и свободный username с окончанием `bot`. Используйте отдельного бота XD: подключение не перезапишет webhook другого сайта.

Сохраните токен в менеджере паролей. **Не отправляйте токен в этот чат, код, коммиты или скриншоты.** `username` указывается без `@`. `/setcommands` при желании:

```text
start - Начать работу
help - Помощь
events - События и запись
join - Записаться на событие по ID
leave - Отменить запись по ID
cabinet - Личный кабинет
stop - Отключить уведомления
unlink - Отвязать бота
```

## 3. Заполнить Vercel → Project → Settings → Environment Variables

Задайте для **Production**, не для чужих preview-сборок:

| Переменная | Значение |
|---|---|
| `APP_ORIGIN` | Точный адрес сайта `https://ваш-домен`, без завершающего `/` |
| `TELEGRAM_BOT_USERNAME` | Username созданного бота без `@` |
| `TELEGRAM_BOT_TOKEN` | Токен BotFather |
| `TELEGRAM_WEBHOOK_SECRET` | Случайный секрет: 32–256 букв/цифр/`_`/`-`, создайте менеджером паролей |
| `SUPABASE_SECRET_KEY` | Серверный secret key проекта Supabase (либо legacy service_role key), никогда publishable/anon |
| `TELEGRAM_BOT_ENABLED` | `true` после заполнения остальных настроек |
| `CRON_SECRET` | Для планировщика: отдельный случайный секрет не короче 32 символов |

Обычные `NEXT_PUBLIC_SUPABASE_URL` и `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` уже должны быть настроены. У перечисленных секретов **не должно быть префикса NEXT_PUBLIC_**. Supabase secret key имеет привилегированный доступ к базе; держите его только в серверном окружении. Для бота не нужно включать `AUTH_TELEGRAM_ENABLED`.

Сделайте Redeploy. Публичный адрес webhook не должен требовать Vercel Authentication или пароль просмотра; авторизацию самого обработчика проверяет отдельный секрет Telegram.

## 4. Подключить webhook без терминала

Войдите владельцем → «Управление» → «Telegram-бот и очередь» (`/admin/telegram`). Подтвердите подключение и нажмите **«Подключить webhook»**.

Приложение проверит, что токен принадлежит указанному боту, затем зарегистрирует `/api/telegram/webhook`. Если бот уже подключён к другому адресу, операция остановится. Существующие обновления не удаляются. Сообщение об успехе означает, что Telegram принял настройку; доставка проверяется следующим шагом.

## 5. Проверить привязку

«Мой аккаунт» → «Telegram-бот и уведомления» → «Начать привязку». Откройте полученную ссылку, нажмите «Начать» в боте. Бот сообщит ваш числовой Telegram ID. Вернитесь на сайт, нажмите «Обновить статус привязки», сверьте ID и подтвердите. Для автоматических сообщений отдельно включите уведомления.

Ссылка действует 10 минут, база хранит только её SHA-256-хеш. Новая ссылка заменяет предыдущую. Другой пользователь Telegram не может заменить уже найденного кандидата. Не передавайте ссылку другим людям. Совпадение username не даёт доступа к чужому профилю.

Проверьте `/events` и `/cabinet`. Ссылка на кабинет требует обычного входа на сайт и не содержит токена входа. `/stop` отключает уведомления, `/unlink` удаляет привязку бота, не затрагивая Supabase Auth/OIDC.

## 6. Повторные попытки без платного сервиса

События, изменения расписания, начисления прайма и отмены начислений создают записи очереди в той же транзакции, что и исходное действие. После действий на сайте и команд боту приложение обрабатывает до 20 сообщений за запуск, с ограничением времени около 20 секунд. Большая очередь или временный сбой требуют следующего запуска.

**Вручную:** `/admin/telegram` → «Обработать очередь». Сначала устраните проблему токена/сети, затем при необходимости подтвердите «Повторить неудавшиеся отправки».

**Через имеющийся GitHub:** подготовлен `.github/workflows/xd-telegram-dispatch.yml`, раз в 10 минут. Он выключен по умолчанию. Для запуска файл должен оказаться в основной ветке репозитория; в текущем draft PR расписание не активно.

На GitHub → Settings → Secrets and variables → Actions:

- Variable `XD_APP_ORIGIN`: тот же HTTPS-адрес сайта, без `/` в конце.
- Secret `XD_TELEGRAM_CRON_SECRET`: то же значение, что `CRON_SECRET` на Vercel.
- Variable `XD_TELEGRAM_DISPATCH_ENABLED`: `true`.

Затем Actions → XD Telegram delivery → Run workflow, проверьте успех и очередь. Токен бота и ключ Supabase передавать GitHub Actions не нужно. Для отключения расписания установите переменную в `false`.

Стандартные GitHub-hosted runners в публичном репозитории доступны бесплатно по правилам GitHub; проверьте тариф и квоты своего аккаунта при изменении видимости репозитория. Scheduled workflows могут задерживаться и отключаются после длительной неактивности публичного репозитория; следите за Actions. Это резервный запуск очереди, не гарантия доставки в конкретную минуту. Vercel Cron не подключается и платный план не создаётся.

## Правила доставки и ограничения

- Только личные чаты; группы, каналы, сообщения от ботов и команды старше 10 минут игнорируются.
- `update_id` защищает от повторной обработки, команды ограничены по Telegram ID. Telegram ID — стабильный идентификатор; username — только подпись.
- Перед выдачей сообщения повторно проверяются действующее членство, блокировка, текущая привязка и подписка. Начисления получает только их владелец. Устаревшее начисление после отмены не доставляется как действующее.
- Одновременно выдаётся только одна отправка. База ограничивает частоту: не чаще одного сообщения в секунду в один чат и до 20 попыток в секунду в целом.
- До пяти попыток, `retry_after` Telegram учитывается. При блокировке бота подписка выключается. Повтор после неоднозначного сетевого сбоя может дать дубликат: Bot API не предоставляет ключ идемпотентности для sendMessage.
- Ответы на команды старше 10 минут и уведомления старше суток отменяются при следующей обработке. Для уже отправляемого сообщения отзыв подписки может не успеть остановить сетевой запрос.
- Индексы обновлений старше 7 дней, завершённые записи очереди старше 30 дней и истёкшие заявки старше суток очищаются при обработке следующих команд; без команд физическая очистка откладывается. Сырые webhook JSON, токены и текст переписки не сохраняются.
- Нет Mini App или административных команд в чате. Запись и уведомления о выплатах доступны после миграции 010.
- Настройки Supabase/OIDC, бот, webhook и публичный деплой необходимо проверить в вашем аккаунте. Локальные тесты их не заменяют.

## Приёмка двумя аккаунтами

1. Привязать два разных Telegram ID к двум подтверждённым участникам; попытаться повторно привязать тот же ID к другому аккаунту — не должно получиться.
2. Без подписки автоматических уведомлений нет; команды работают. Включить подписку и создать будущую активность на сайте — сообщение появляется в личном чате.
3. Внести/изменить событие, проверить `/events`; отменить его, проверить актуальный статус в уведомлении.
4. Начислить долю прайма одному участнику: второй не получает чужую сумму. Отмена начисления отражается отдельным сообщением.
5. Заблокировать участника: новые приватные данные не выдаются. Отвязать бота, затем привязать другой ID: старый чат не получает ожидающие уведомления.
6. Проверить временный сбой, очередь, ручной и запланированный запуск, отключение через `/stop`, отсутствие секретов в клиентской сборке.

Официальные источники: [Telegram Bot API / webhook / sendMessage](https://core.telegram.org/bots/api), [GitHub Actions usage](https://docs.github.com/en/billing/managing-billing-for-your-products/managing-billing-for-github-actions/about-billing-for-github-actions), [расписание Actions](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule).

## Запись и выплаты — обновление 010

Если 001–009 уже выполнены, примените только 010, затем обновите приложение. Секреты и существующий webhook сохраняются. В /events появятся ваш текущий статус записи и кнопки. Кнопка открывает чат бота со служебной командой; если Telegram показывает «Начать», нажмите её. Поддерживаются также `/join ID_события` и `/leave ID_события`.

Повторная запись не создаёт дубль; действия относятся только к вашему участнику. Начавшиеся, отменённые и завершённые события закрыты для изменения записи. На сайте и в боте используется одна таблица. Ответ показывает текущее состояние на момент доставки; запись не является отметкой присутствия.

При включённой подписке бот уведомляет о записанной казначеем выплате и её отмене. Показываются точная сумма и текущий остаток по соответствующему начислению. Доставку контролирует прежняя очередь; бот не переводит золото в игре. Полный сценарий приёмки: [STAGE6B.md](STAGE6B.md).
