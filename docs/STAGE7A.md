# Этап 7A — личный кабинет Telegram Mini App

Первый самостоятельный модуль Mini App подготовлен в коде. Он показывает данные; финансовые операции и запись/отмена остаются на существующем сайте и в боте. Дизайн по-прежнему отложен, B0/S1/F1 сохранены. Оригинальное Express-приложение не меняется.

## Что доступно

- `/mini-app`: личная подтверждённая посещаемость недели/месяца, начисления/выплаты периода и текущий долг за всё время.
- До 10 ближайших событий своей гильдии, собственный статус записи и ссылка на событие сайта. Список не зависит от периода статистики; запись не является присутствием.
- Пустые состояния, повтор после ошибки, ограничение запросов, объяснение отсутствия привязки и истечения доступа. Кнопки «Неделя», «Месяц», «Обновить данные».
- Даты UTC совпадают с дашбордом и ботом. Сезон остаётся без дат, правила прайма/мини РБ не меняются. Суммы форматируются точно до 0,0001 золота.

## Подключение с телефона

1. Нужен HTTPS-сайт, действующий бот и подтверждённая на сайте привязка участника. Сначала завершите SETUP.md и TELEGRAM.md, проверьте /stats.
2. Примените только недостающие миграции до `202611020012_telegram_mini_app.sql` по порядку. Если выполнены 001–011, нужна только 012. Старые миграции не повторять.
3. В Vercel → Project → Settings → Environment Variables добавьте **серверный** `TELEGRAM_MINI_APP_ENABLED=true` для нужного окружения и обновите приложение. Используются прежние APP_ORIGIN, Supabase и секреты бота. Новых токенов нет; webhook не перенастраивается.
4. В официальном [@BotFather](https://t.me/BotFather) откройте `/mybots` → своего бота → Bot Settings → Menu Button → Configure menu button (либо команду `/setmenubutton`). Введите точный HTTPS-адрес `https://ваш-домен/mini-app` и подпись «Кабинет XD». Названия пунктов Telegram могут меняться. Это настройка меню, не новый webhook.
5. Откройте личный чат бота, нажмите появившуюся кнопку меню. Доступ получает только существующий одобренный участник с подтверждённой привязкой этого Telegram ID. Обычное открытие URL в браузере не авторизует игрока.
6. Пройдите приёмку ниже на телефоне и компьютере. Настройки окружения сами по себе не подтверждают работоспособность.

Вход через Telegram OIDC и вход email/пароль на сайте не меняются. Mini App не создаёт Supabase-сессию: при переходе на сайт может потребоваться обычный вход. Новые участники по-прежнему регистрируются и ожидают одобрения на сайте.

Для отключения поставьте `TELEGRAM_MINI_APP_ENABLED=false`, обновите приложение и при желании уберите Menu Button в BotFather. Обычный сайт и бот продолжают работать, данные и миграции удалять не нужно. Без флага/настроек выводится сообщение «Мини-приложение ещё не подключено».

## Доступ и ограничения

Сервер получает исходный initData в теле POST и проверяет HMAC-SHA-256 по официальному алгоритму Telegram Bot Token. Все поля, кроме hash, входят в подпись, включая необязательный signature. Дубликаты ключей, невалидный формат, изменённые данные, неверный токен и старый auth_date отклоняются. Telegram ID извлекается только после проверки; username и initDataUnsafe не используются.

Срок подтверждения запуска — 5 минут, допустимое опережение часов 30 секунд. После истечения закройте Mini App и откройте заново из меню бота. Собственной долговечной сессии нет. Повтор запроса в пределах срока допустим только для чтения. Лимит — 20 запросов на Telegram ID в минуту, общий для всех экземпляров сервера. Каждый запрос заново проверяет привязку, активное членство и блокировку. Уже отправленный или выполняющийся ответ нельзя гарантированно отозвать.

POST принимает только JSON initData/period со своего Origin, до 16 КиБ. Сервисный RPC недоступен browser/anon; таблица лимитов закрыта RLS и отсутствием прямых grants, в ней только ID, начало окна и счётчик. Старые окна удаляются при следующих запросах; без запросов очистка откладывается. initData, токены, сырые профили Telegram и финансовый ответ в логи приложения не пишутся. Не добавлять аналитику/проксирование с записью тел этого endpoint.

Личные данные не кэшируются и не сохраняются в localStorage/sessionStorage/cookie. При скрытии экрана, ошибке и истечении они убираются; при возвращении выполняется новая проверка. Только оболочка `/mini-app` допускает iframe от https://web.telegram.org. Остальные страницы сохраняют X-Frame-Options DENY и frame-ancestors none. Другие web-клиенты потребуют отдельной проверки; мобильные/desktop Telegram WebView также требуют живой приёмки.

## Приёмка двумя аккаунтами

1. Откройте Mini App двумя привязанными участниками; каждый видит собственный ник, суммы и посещаемость. Сравните те же UTC-периоды с /stats и дашбордом.
2. Проверьте неделю/месяц, обновление, длинный ник, большое число золота, пустую посещаемость и отсутствие будущих событий. Процент без знаменателя — «Нет данных».
3. Выполните запись на сайте/в боте, затем обновите Mini App: статус совпадает. Измените/отмените выплату на сайте и проверьте актуальные итоги; сам Mini App ничего не начисляет и не выплачивает.
4. Откройте URL вне Telegram и неподтверждённым Telegram-аккаунтом: личные данные не выдаются. Подмена ID или initData в браузере также не даёт доступа.
5. Заблокируйте участника или отвяжите Telegram на сайте, обновите Mini App: данные скрыты. После пяти минут нужно закрыть и заново открыть его. Проверьте сворачивание/возврат и отключение сети с повтором.
6. Проверьте меню и экран в актуальных Telegram Android/iOS/Desktop и Web, после чего подтвердите готовность публичного запуска.

## Проверка разработки

Итог локальной проверки: 110 результатов автоматических тестов без ошибок, TypeScript и production-сборка, 19 конкурентных сценариев PostgreSQL 17. Пройдены HTTP-стенды бота и Mini App, а также 32 комбинации состояния/ширины в Chromium (320, 390, 768, 1440 px): переключение периода, обновление, повтор после ошибки, скрытие и возврат после блокировки; горизонтальных переполнений и JS-ошибок нет. В финальных проверках новых ошибок не обнаружено.

`npm run check` — TypeScript, автоматические протокольные/SQL-тесты и production-сборка. `python3 scripts/check-mini-app.py` после сборки проверяет настоящий Next HTTP с локальной заменой Supabase, синтетическими подписями и запретом внешних запросов; включён в CI. С ключом `--browser` добавляется Chromium (нужны локальные Python Playwright и `/usr/bin/chromium`), официальный SDK заменяется тестовым объектом; скриншоты явно подписаны как демонстрационные.

`python3 scripts/check-treasury-postgres.py` проверяет параллельные запросы в отдельном PostgreSQL 17, включая лимит Mini App, блокировку участника во время ожидания и очистку старых окон без ожидания чужой блокировки. Не использовать рабочую базу для тестов. Эти проверки не заменяют настоящие Supabase/Auth/PostgREST, Telegram SDK, меню Telegram и публичный деплой; они пока не подтверждены.

Источник алгоритма и настройки меню: [Telegram Mini Apps](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app). Новых платных компонентов нет, действуют квоты существующего хостинга и базы.
