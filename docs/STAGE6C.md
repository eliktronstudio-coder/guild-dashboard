# Этап 6C — личная статистика Telegram

## Реализовано

Миграция `202611010011_telegram_stats.sql` после 001–010, затем обновление приложения. Предыдущие миграции не изменены. Сохраняются привязки, очередь, старые команды и сигнатуры RPC. Новых секретов, библиотек и инфраструктуры нет; существующий webhook сохраняется.

`/stats` и `/stats month` показывают текущий месяц, `/stats week` — неделю с понедельника. Кнопки в ответе, помощи и кабинете бота открывают соответствующую команду. Пересланная кнопка относится только к нажавшему участнику, идентифицированному по Telegram ID. Даты UTC указаны явно; это соответствует дашборду. Сезон остаётся без дат, произвольные даты доступны на сайте.

Посещаемость: только применимые подтверждённые завершённые учитываемые события, не из будущего; present/(present+absent). Excused/excluded исключены. Без знаменателя — «Нет данных», нулевые финансовые суммы — 0.

Начисления — действующие распределения по дате создания; выплаты — действующие записи выплат по их дате создания. Отмены обновляют итог первоначального периода; это не историческая сводка движения казны. Текущий долг за всё время выводится отдельно. Суммы считаются в PostgreSQL и передаются десятичными строками без потери 0,0001 золота. Правила прайма 70/30 и мини РБ не меняются.

Границы периода сохраняются при приёме команды. Перед выдачей задания пересчитываются значения и проверяются членство, блокировка и поколение привязки. Приватный SQL-агрегат недоступен браузерным ролям и напрямую service_role; его вызывает защищённая очередь. Входящие команды не принимают ID участника. Ответ доступен без добровольной подписки; никакие начисления/выплаты команда не создаёт.

## Проверка после подключения

1. Применить только недостающие миграции до 011; обновить приложение. При желании добавить `stats` в /setcommands BotFather.
2. У двух участников с разными Telegram ID запросить /stats. Каждый видит только свои суммы и посещаемость, включая при выключенных уведомлениях.
3. Проверить /stats week, /stats month и кнопки; сравнить те же UTC-даты с дашбордом и личным балансом сайта. На первом дне месяца недельный и месячный периоды могут сильно различаться.
4. Без учитываемых событий получить «Нет данных». Снять подтверждение отчёта и убедиться, что событие перестало влиять на процент.
5. Сделать частичную выплату, проверить итог; отменить выплату и проверить восстановление долга. При старом начислении и новой выплате остаток не равен разности сумм периода — это ожидаемо.
6. Заблокировать участника или отвязать бота до выдачи сообщения: ожидающий ответ не должен содержать личные данные. Отдельно проверить новую привязку.

## Проверки и ограничения

Пройдено локально: 102 результата автоматических тестов, TypeScript и production-сборка; 16 конкурентных сценариев на отдельном PostgreSQL 17 со всеми миграциями до 011. Production HTTP-стенд прошёл, включая /stats, /stats week, мобильную ссылку месяца и отказ от команды с чужим ID. Новых ошибок в итоговых проверках нет.

Локальные тесты используют только синтетические записи и тестовую auth-схему. SQL-проверки сопоставляют собственные показатели бота с существующими RPC сайта; проверяют отсутствие данных, границы периода, исключения посещаемости, исправления, дубликаты, права и смену привязки. HTTP-стенд проверяет настоящий Next-обработчик с локальной заменой Supabase и запрещёнными внешними запросами.

Живые Supabase/Auth/PostgREST, настоящий Telegram, кнопки его клиентов и публичный деплой ещё не подтверждены. Для уже выданного на отправку сообщения отзыв доступа может не успеть остановить сетевой запрос. После неопределённого сетевого сбоя Bot API может доставить повтор; существующие ограничения очереди сохраняются. Следующий шаг — подключение и приёмка, затем отдельный модуль Mini App.
