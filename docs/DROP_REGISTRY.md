# Реестр дропа администратора

Адрес: https://xd-guild.ru/admin/drops, ссылка «Реестр дропа» в управлении гильдией.

Поля: фото (PNG/JPEG/WebP до 10 МБ, нормализуется в PNG 100×100), название до 120 символов, справочная цена за единицу в золоте с двумя десятичными знаками. Фото можно заменить или убрать. Есть поиск, страницы по 20 записей, редактирование и удаление с подтверждением.

Реестр независим от фактического дропа событий, продаж и распределений. Изменение цены и удаление записи не меняют финансовую историю. Создание, редактирование и удаление записываются в аудит. Права `drops.manage` выдаются только владельцу и администратору; чтение защищено RLS, изменения — проверками RPC. Версии защищают от перезаписи одновременных правок.

## Включение на рабочем Supabase

В Supabase → SQL Editor выполнить целиком [202611090019_drop_registry.sql](../apps/web/supabase/migrations/202611090019_drop_registry.sql), затем обновить реестр. Миграция совместима с рабочими 001–016, не требует 017/018, выполняется одной транзакцией и допускает повторный запуск. Создаёт только независимую таблицу реестра, разрешение, RPC и политику доступа. Существующие аккаунты, события, финансы и схемы распределения не меняет.

Доступный приложению Supabase secret key не предоставляет SQL-доступ к изменению схемы. Пока миграция не применена, страница показывает сообщение о необходимости настройки, формы записи не показываются. Необходимо отдельно выполнить SQL через Supabase SQL Editor либо предоставить доверенный канал для запуска миграции; пароли не следует публиковать в чате.

Проверки: PostgreSQL (PGlite) на схеме 001–016 — создание/редактирование/удаление, повтор миграции, RLS и запреты прямых изменений, аудит, дубли названий, точные большие суммы и конфликты версий. Браузерная проверка production Next с локальной имитацией Supabase — загрузка фото, создание, изменение, удаление, шесть разделов на шести ширинах и в двух темах. Локальные проверки не используют рабочие аккаунты или данные.
