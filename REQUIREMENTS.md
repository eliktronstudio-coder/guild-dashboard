## Неопределённости, которые нельзя замаскировать реализацией

1. Игра уточнена — ArcheAge. Сервер, допустимые символы ников, справочники классов, единица учёта золота и часовой пояс гильдии ещё требуют уточнения.
2. Предлагаемые правила уважительных причин и округления находятся в DECISIONS.md. До принятия они не правила гильдии.
3. Нужны реальные тексты правил и обработки данных; макет содержит только примеры подписей согласий.
4. Email в конечной платформе обязателен как альтернативный способ. Возможен Telegram-first запуск только после согласования этой границы релиза.
5. Макеты поздних модулей показывают расположение элементов, но не обещают их наличие в первом запуске.

## Этап 6 — первый модуль Telegram

Бот работает с существующим одобренным членством; не создаёт профиль, не объединяет аккаунты и не меняет OIDC-идентичность. Сайт выдаёт одноразовую ссылку (10 минут), бот подтверждает числовой ID, пользователь повторно подтверждает его на сайте. Уведомления требуют отдельной подписки. /events выдаёт только будущие события активному участнику, /cabinet — обычную ссылку без входного токена. /stop и /unlink доступны владельцу Telegram-привязки даже при блокировке членства, не раскрывая данные гильдии.

Очередь событий/начислений создаётся транзакционно; финансовые уведомления адресуются только получателю. Перед отправкой повторно проверяются членство, блокировка, подписка, поколение привязки и актуальность начисления. Проверка секретного заголовка Telegram, ограничение тела запроса, свежесть команды, уникальный update_id, частота и ограниченные повторы обязательны. Отправка может повториться при неоднозначном сетевом сбое; обещание exactly-once для Bot API не даётся.

## Этап 6B — запись и уведомления о выплатах

Бот изменяет только запись своего привязанного участника на будущее событие своей гильдии. Запись/отмена абсолютны, не являются переключателем и безопасны при повторном update_id. Проверки статуса события, членства, блокировки и актуальной привязки выполняются после ожидания блокировки события. Сайт использует тот же внутренний обработчик; реальное изменение журналируется с источником site/telegram. Запись не подтверждает присутствие и не влияет напрямую на начисления.

Частичные выплаты и их отмены создают персональные уведомления транзакционно. Перед доставкой сверяются получатель и текущий статус выплаты; отменённая выплата не отправляется как действующая. Остаток показывается по конкретному начислению, целочисленно. Бот сообщает ручную запись казначея и не переводит золото в игре.

## Этап 6C — личная статистика бота

- `/stats` (месяц), `/stats week`, `/stats month` и кнопки открывают только данные текущей подтверждённой привязки; ID другого участника в команде не принимается.
- Неделя начинается в понедельник UTC, месяц — первого числа. Конец — текущий день включительно; границы фиксируются при запросе, показатели читаются перед доставкой.
- Посещаемость следует правилам сайта: только подтверждённые завершённые учитываемые события, применимые к игроку; present/(present+absent), excused/excluded исключены, без знаменателя «Нет данных».
- Начислено/выплачено за период считаются по датам создания действующих записей с учётом текущих отмен. Остаток к получению показывается отдельно за всё время; это не начисления минус выплаты выбранного периода.
- Ответ по команде доступен без подписки на уведомления. Отзыв членства, блокировка или замена привязки отменяют ещё не выданные ответы; для уже начатой отправки сохраняется ограничение Bot API.
- Новых денежных операций, дат сезона, правил мини РБ и функций Mini App этот модуль не вводит.

## Этап 7A — личный кабинет Mini App

- Публичная оболочка `/mini-app` не содержит личных данных. Они загружаются через POST только после серверной HMAC-проверки оригинального `initData` и `auth_date`; `initDataUnsafe`, Telegram username и данные клиента не являются основанием доступа.
- Срок доступа по подписанному запуску — 5 минут, допустимое опережение часов — 30 секунд. Повторный запрос в пределах срока допустим только для чтения; каждый раз проверяется текущая подтверждённая привязка, активность членства и блокировка. После истечения нужно заново открыть Mini App.
- Только собственная статистика недели/месяца по правилам этапа 6C и предстоящие события своей гильдии с собственным статусом записи. Нет административных и финансовых операций, новой регистрации и автоматического создания Supabase-сессии.
- POST ограничен своим Origin, JSON до 16 КиБ, полями initData/period. База ограничивает чтение до 20 запросов на Telegram ID в минуту; browser/anon не имеют доступа к сервисному RPC и закрытой таблице лимитов.
- Секрет бота, initData и личные показатели не сохраняются в browser storage, cookie или журнале приложения. При ошибке/истечении/скрытии экрана личные данные убираются; ответ не кэшируется.
- Оболочку разрешено встраивать только web.telegram.org. Остальные страницы сохраняют запрет iframe. Отдельный флаг по умолчанию выключен; без конфигурации показано честное состояние недоступности.
