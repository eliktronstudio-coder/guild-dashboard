# GPT Vision в существующем боте XD

Основной разбор состава — OpenAI Responses API, `gpt-5.4-mini`, изображения `detail: original`. Оригинал передаётся вместе с увеличенными цветными ячейками. Каталог игроков не передаётся модели: точные имена и зарегистрированные альтернативные персонажи сопоставляются локально с `/api/discord/context`. Уверенно прочитанные похожие ники и длинные уникальные начала сопоставляются автоматически при явном отрыве от других кандидатов. Неоднозначные и плохо читаемые ники требуют ручного подтверждения; автоматические сопоставления помечаются отдельно. Сохраняются исходное чтение, группа, выбранный ник и ID игрока. Дроп продолжает обрабатывать существующий Tesseract. Если локальный детектор не выделил ячейки или обнаружил слияние полупрозрачных панелей с голубым фоном воды/неба, GPT получает исходный скриншот и сам находит все надписи состава. Частично найденные ячейки не задают предел числу участников. Этот режим использует те же суточные/месячные лимиты, очередь и кэш. Все имена из такого разбора требуют ручного подтверждения; у них нет выдуманных координат и кнопка платного перечитывания отдельных фрагментов недоступна. При отсутствии ников GPT возвращает пустой список вместо шума из интерфейса. Обычный разбор выделенных ячеек и Tesseract остаются доступными.

Без ключа и при ошибках/лимитах работает Tesseract. В импорте доступны единая кнопка «Распознать скрины» и «Перечитать спорные GPT». Tesseract включается автоматически при недоступности GPT; отдельной кнопки нет. Повторный анализ отправляет только спорные ячейки; ручные исправления, игнорирование шума и дроп сохраняются. После любого разбора проверяйте состав перед публикацией.

## Подключение на Timeweb

Существующий `xd-discord-bot.service` использует `EnvironmentFile=/etc/xd-discord-bot.env`. Откройте файл через `sudoedit /etc/xd-discord-bot.env`, сохраняя все существующие строки. Добавьте или обновите **только**:

```dotenv
OPENAI_API_KEY=<секретный ключ из OpenAI Platform>
OPENAI_MODEL=gpt-5.4-mini
```

Не присылайте ключ в чат, не добавляйте в GitHub или настройки фронтенда. Рекомендуется отдельный OpenAI project с ограниченным бюджетом. ChatGPT-подписка не предоставляет API-кредиты. Создайте API project, подключите оплату и создайте project API key в https://platform.openai.com/api-keys.

После сохранения:

```sh
sudo chmod 600 /etc/xd-discord-bot.env
sudo systemctl restart xd-discord-bot.service
sudo systemctl is-active xd-discord-bot.service
```

Код не перезаписывает env-файл. Схема автодеплоя не меняется. Панель Discord/канала остаётся на https://xd-guild.ru/admin/discord; ключ GPT задаётся исключительно на VPS.

## Локальные ограничения

Параметры перечислены в `.env.example`. По умолчанию: без суточного лимита (`OPENAI_DAILY_LIMIT=unlimited`), 2 одновременно, месячный предел $5, таймаут 60 секунд, без автоматических повторов SDK. Суточная/месячная граница — Asia/Yekaterinburg. Явное числовое значение `OPENAI_DAILY_LIMIT` позволяет при необходимости снова включить суточный лимит; `0` отключает платные вызовы. Можно уменьшить бюджет; значение выше $5 отклоняется. Нулевой бюджет или дневной лимит отключает платные вызовы.

SQLite `/var/lib/xd-discord-bot/drafts.sqlite` содержит учёт запросов и кэш чтения (30 дней, максимум 500 изображений). Ключ кэша зависит от нормализованных исходных пикселей, модели, версии инструкции, сервера и выбранных фрагментов. Исходные изображения и API-ключ в эти таблицы не записываются. Кэш хранит чтение, а не готовые привязки аккаунтов: каталог проверяется заново.

Перед вызовом резервируется верхняя оценка стоимости: 400000 входных токенов по $0.75/млн + лимит выходных токенов по $4.50/млн. После ответа резерв заменяется фактическим usage, без скидки за cached input (консервативно). При потере ответа/неизвестном usage резерв остаётся списанным; поэтому лимит может остановить GPT раньше $5. Явный отказ API (например 401/429) снимает денежный резерв, но учитывает попытку в суточном лимите. Учёт сохраняется после перезапуска, охватывает все серверы этого экземпляра и не контролирует другие приложения, использующие тот же OpenAI project. В логах — только безопасный код ошибки, токены, модель и оценка стоимости.

## Проверка без расходов

`npm test` использует исключительно имитации OpenAI. Тесты проверяют исходные изображения, structured output, кэш, лимиты/конкурентность, ошибки, спорные фрагменты, точные ID и ручную проверку. Реальное качество и доступность модели проверяются отдельным разрешённым запуском после установки ключа.

## Отказ OpenAI по региону (403)

`unsupported_country_region_territory` означает региональное ограничение доступа к OpenAI. Замена OCR-настроек или повторная отправка того же скриншота не исправит такой отказ. Бот показывает причину и использует Tesseract; автоматических повторов нет.

Для GPT необходимо разрешённое OpenAI размещение и доступный API-проект. Можно перенести **только Discord-worker** на подходящий VPS, оставив сайт и базу на текущем сервере: бот использует существующий защищённый HTTPS API `https://xd-guild.ru/api/discord/`. Проверьте поддержку страны у OpenAI перед выбором региона хостинга. Секреты переносятся безопасно в `/etc/xd-discord-bot.env`, а SQLite с памятью ников и бюджетом — в `/var/lib/xd-discord-bot`. Старый экземпляр должен быть остановлен перед запуском нового, чтобы не было двух обработчиков и двух независимых бюджетов. Платный тест требует отдельного разрешения.

## Выделенный обработчик Render

`VISION_SERVICE_URL=https://<имя-сервиса>.onrender.com` и `VISION_SERVICE_SECRET` переключают существующий модуль на `apps/vision-service`. В этом режиме ключ OpenAI нужен **только на Render**; наличие или ошибки сервиса никогда не приводят к прямому запросу OpenAI с VPS. Общие prompt/schema используются обоими режимами. Ответы по-прежнему проходят проверку и сопоставление на Timeweb. Изображения отправляются по HTTPS в подписанном запросе; URL внешних картинок, произвольные промпты и модели не принимаются. Ники и API-ключ в журналы не записываются.

SQLite с постоянным кэшем и основным бюджетом остаётся на Timeweb. Render дополнительно ограничивает параллельность и стоимость в памяти процесса; эти дополнительные счётчики и 10-минутный кэш повторов сбрасываются при его перезапуске. Постоянные лимиты Timeweb при этом сохраняются. Бесплатный Render может засыпать: таймаут удалённого режима по умолчанию 120 секунд, максимально 180 секунд. При сбое сервис не повторяет OpenAI-запрос, бот переходит на Tesseract.

Проверки `/health` и защищённый `/ready` не запускают распознавание. `/ready` проверяет только метаданные модели, без платной генерации. Полноценный платный разбор для тестирования требует отдельного разрешения.

Мелкие исходники без выделенных ячеек передаются вместе с увеличенной копией (до ×4, не более 1600 px по длинной стороне) в одном запросе. Инструкция сохраняет порядок букв и повторяющиеся слоги. Для длинных ошибочных чтений допускаются подсказки с четырьмя правками; это только варианты для ручного выбора, не автоматическое назначение ID игрока. Новая версия ключа кэша позволяет перечитать старые ошибочные результаты обновлённой инструкцией.

## Импорт скриншотов в Discord

Бот автоматически распознаёт изображения новых сообщений в настроенном канале и его ветках: первый скрин — состав, остальные — дроп. Результат публикуется ответом без стартовой кнопки. После распознавания автор выбирает активность, PvE/PvP и Прайм/Мини РБ и подтверждает состав; автоматического сохранения на сайт нет. Обработка идёт последовательно, повторное событие того же сообщения не запускает новый разбор даже после перезапуска (учёт хранится 30 дней). Для ручного повтора используйте «Приложения → Добавить на сайт» либо `/activity message_id:<ID>`. Первое вложение — состав, все последующие — дроп; подпись сообщения не разбирается как дроп. Одна кнопка «Распознать скрины» читает оба вида; без скринов дропа сохраняется только состав.

«Добавить скрины дропа» открывает загрузку до 10 файлов PNG/JPEG/WebP (каждый до 12 МБ). Можно добавлять следующие партии в тот же черновик и снова нажимать «Распознать скрины»: обработанные скрины не перечитываются, одинаковые файлы не учитываются дважды. Весь распознанный дроп суммируется. Из-за ограничения существующего API сайт получает до 8 подтверждающих изображений: состав и первые 7 скринов дропа. Ручные исправления состава и уже прочитанного дропа сохраняются при добавлении новой партии.

Результат показывает три списка: подтверждённые ники, ники для проверки, дроп; полный отчёт прикреплён файлом. В «Выберите игрока или действие» пункт «Из состава» открывает быстрый поиск ника по всему каталогу сайта. Пустой запрос показывает всех игроков, страницы по 25. Выбор подтверждает только выбранную спорную строку; неизвестный ник не заменяется похожим автоматически. Перед публикацией состав по-прежнему необходимо подтвердить. Кнопки старых черновиков временно поддерживаются для совместимости.

## Коэффициент отдельной активности

Четвёртая строка выбора активности показывает коэффициент из реестра сайта и выбранное значение. Нажмите её, чтобы ввести свой коэффициент (0,01–1000, до двух знаков; точка или запятая). При выборе другой активности снова подставляется её базовое значение. Редактирование не запускает повторное распознавание. Выбранный коэффициент отправляется как реальный вес события и участвует в существующем расчёте взвешенной посещаемости отдельно для Прайма и Мини РБ; реестр не меняется. Защита версии реестра, проверка состава и защита от повторного импорта сохраняются. Для ввода коэффициента необходимо применить миграцию `202611200057_discord_activity_coefficient.sql`.

В подтверждении сохранения дата создания отображается по `Europe/Moscow` с отметкой «МСК». Часовой пояс учёта месячного бюджета остаётся прежним, чтобы изменение отображения не сбрасывало финансовые ограничения.

## Добавление и удаление участников перед сохранением

В меню спорного ника «Добавить в активность — ник из состава» открывает поиск по зарегистрированным игрокам и подтверждает выбранную строку. «Убрать из активности» исключает эту строку из состава. Отдельные кнопки при проверке состава позволяют добавить пропущенного игрока, даже когда спорных ников уже нет, или убрать любого подтверждённого участника/гостя. Выбор игрока идёт по реальному ID сайта, без дубликатов. Изменения попадают в публикуемый список участников и сохраняются при перечитывании спорных фрагментов; ручное добавление не выдаётся за результат OCR и не создаёт ложных примеров для памяти ников. Работа идёт в черновике до подтверждения сохранения.

При добавлении игрока или выборе «ник из состава» сразу показывается полный алфавитный список сайта, по 25 ников на страницу (ограничение Discord). «Быстрый поиск ника» открывает ввод части имени; «Все ники» снимает фильтр и возвращает полный список без обязательной отправки пустой формы.

## Проверка дропа

Распознавание дропа сохраняет существующий Tesseract и не отправляет новых платных запросов. После чтения точные названия и однозначные небольшие опечатки сопоставляются с действующим каталогом сайта. При сопоставлении учитываются похожие кириллические/латинские буквы и несколько опечаток; длинное обрезанное начало допускается только при однозначном совпадении. Различающиеся числа в названиях наборов, близкие варианты, короткие фрагменты и непрочитанное количество остаются на проверке. При открытии проверки дропа старые спорные строки повторно сопоставляются без платного распознавания; исходное чтение и ручные исправления сохраняются. Исходная строка и окончательный предмет хранятся отдельно в черновике и отчёте.

«Проверить / исправить дроп» открывает строки распознавания. Выберите строку и предложенный предмет либо «Из реестра — поиск предмета». В реестре первый пункт «Найти предмет…» открывает поиск по части названия; пустой запрос показывает весь каталог. После выбора предмета подтвердите целое количество 1–1 000 000. Доступны исправление количества, добавление предмета, удаление строки и прежнее редактирование текстом. Дубли суммируются, ручные исправления сохраняются при добавлении следующих скриншотов. Спорный дроп блокирует сохранение с дропом; явное сохранение только состава остаётся доступным.
