# XD Guild Command Center

XD / ХД is a Russian-language guild interface for ArcheAge. The existing application provides authenticated member access, role-controlled guild information, member records, activities, attendance and treasury/payroll views. Financial figures and protected actions use the existing application data and permission rules; the visual transfer does not change calculation formulas or transfer gold in the game.

The owner approved transferring the visual system of http://xd.200.165.236.194.sslip.io across xd-guild.ru. Current visual guidance is in [docs/DESIGN.md](docs/DESIGN.md); the approved implementation boundary is in [.impeccable/surfaces/reference-ui.md](.impeccable/surfaces/reference-ui.md).

The dashboard supports existing saved panel layouts and a reset control. Its Moscow-time game countdown is an explicit static weekly rotation, separate from real recorded/scheduled activities; it does not create attendance. Existing imagery is reused. Dark/light themes and mobile navigation serve the same real application features, without simulated translations or invented account attributes.

Temporary pause (2026-11-16): the owner requested hiding the dashboard calculation-period selector, closing reminder, end-date countdown and archive/closing navigation. The archive page and close server action are paused by `PERIOD_CLOSING_ENABLED = false`; historical records, existing attendance/payroll formulas and statistical date filtering are retained for the later redesign. The game-activity countdown remains independent and available.

While periods are paused, attendance defaults to the entire saved activity history on the dashboard, statistics, roster, attendance report and Mini RB purchase candidates. A dedicated authenticated all_time_attendance_report reads source counts and Prime weights with unbounded dates and existing guild/member permissions. Historical accounting partitions are used only to preserve recorded financial obligations; they do not reset attendance. Roster salary totals sum the original outstanding obligations across those partitions; this does not redistribute funds across history, rewrite allocations or reverse paid gold. Unavailable/incomplete history is an error, never a substitute zero. Dashboard RPC reads are partitioned into at most 365-day windows to respect the existing API limit without truncating the lifetime range.

Performance (2026-11-16): dashboard/statistics receive one authorized `command_attendance_data` snapshot with the shared event catalog, permitted member list and present marks. It replaces repeated joined attendance pages and per-row RLS evaluation; classification, totals and date bounds remain unchanged. Snapshot and aggregate reports start concurrently. Financial history reads and lifetime attendance also start concurrently. Auth/role checks still run for every request, without a shared cache or stale payroll data.
