# Дорожная карта

Подробный перечень работ и решений по всем этапам — [CHECKLIST.md](CHECKLIST.md). Выполнять блоки последовательно; список конечной платформы не является планом одновременной реализации.

| Этап | Результат | Условие завершения |
|---|---|---|
| 0 — проектирование | Концепция, макеты, модель данных, правила, оценка бесплатного старта | Проверка материалов + выбор дизайна и архитектуры владельцем |
| 1 — основа | Отдельная Next.js-версия, CI, Supabase, бренд, вход, ник, согласия, заявки, одобрение, роли, кабинет, блокировка/сессии, первый деплой | Новый игрок проходит весь путь; до одобрения доступ закрыт; повторная заявка безопасна; права и RLS проверены; откат и резервная копия проверены |
| 2 — состав | Список с поиском/сортировкой, профиль, несколько персонажей, история ника | Мобильный сценарий, приватность профиля, атомарная смена ника; принятие миграции |
| 3 — активности | События, календарь, применимость, посещаемость, отчёты | Будущие/отменённые/неприменимые исключены; новые участники не штрафуются за старые события; правки журналируются |
| 4 — казна | Партии, продажи, доли, начисления, выплаты, обязательства, журнал | 30/70, округление, частичная продажа, конкурентные запросы и откаты проходят проверки; баланс сходится |
| 5 — дашборд | Реальные агрегаты/графики/рейтинги и фильтры | Итоги совпадают с исходными записями и выбранными датами; персональные данные видны по правам |
| 6 — Telegram | Привязка, /start, /events, /me, уведомления | Проверены подписи/секрет webhook, дедупликация update_id, повторные попытки, отписка/блокировка бота |
| 7 — развитие | Mini App, запись/присутствие через бота, достижения | Отдельные критерии для каждого расширения; подлинность initData |

Telegram для аутентификации появляется на этапе 1, функциональность бота — на этапе 6. Email/пароль включается на этапе 1 при наличии SMTP либо отдельным завершением этапа 1 после его настройки; не объявлять этап полностью соответствующим ID-01/ID-05 без этого.

Перед каждым этапом — уточнить правила. После каждого — обновить README, REQUIREMENTS, ROADMAP, CHANGELOG, DECISIONS, TODO и сообщить результат, проверки, ошибки, ограничения, требуемые действия владельца, следующий шаг.

Новый код разрабатывается отдельно от существующего runtime. До переключения: инвентаризация → резервная копия → пробный импорт → сверка → проверка регрессий → согласованное переключение. Старые аукцион, калькулятор рейдов и отчёты сохраняются доступными до переноса их задач.


Уточнение этапа 0 (концепция 02): фотографические фоны и motion-поведение подготовлены для просмотра. На этапе 1 перенести доступные эффекты в общие компоненты; проверить на реальном телефоне, отдельно загружать адаптивные изображения и оценить LCP/CLS. Текущие проверки — только прототип Chromium.

## Уточнение дизайн-этапа

Полный макет строится в Figma с последовательным выбором шрифтов, палитры/бренда, визуала, компонентов, отдельных экранов desktop/mobile и прототипа. Историческое правило: разработка ожидала полного дизайна. **2026-10-31 владелец явно отложил дизайн и поручил продолжить создание; это ограничение снято для разработки основы.** Выбраны B0, S1 и основной фон F1 «Гавань под луной». Следующий этап F-04 — направление эмблемы XD, затем её варианты в разных размерах. Кадрирование и затемнение F1 уточняются в полных экранах. Перенос локальных материалов в Figma ожидает восстановления доступа после лимита MCP Starter.
